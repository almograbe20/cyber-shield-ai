# 🛡️ Cyber Shield AI — موقع كشف الثغرات الأمنية بالذكاء الاصطناعي

مشروع تخرّج — منصة ويب تكتشف الثغرات الأمنية في الكود وتشرحها وترتّبها بالذكاء الاصطناعي.

> **ملاحظة:** واجهة الموقع كلها بالإنجليزية (الاسم: **Cyber Shield AI**)، وهذا الملف
> شرح لك بالعربي. مخرجات الفحص وشروحات الـ AI تظهر للمستخدم بالإنجليزية.

> هذا الملف هو **الكشف الكامل للمشروع** (كما طلبت كشريك): كل شيء مشروح — البنية،
> الملفات، آلية العمل، والخطة من البداية حتى قسم الـ attack على المواقع.

## 📍 أين نحن الآن؟

| المرحلة | الوصف | الحالة |
|---|---|---|
| **1. صفحة الويب (MVP)** | واجهة + محرك فحص حقيقي + طبقة AI (محلية) | ✅ منجزة |
| **2. قاعدة البيانات** | حسابات + تسجيل دخول + حفظ الفحوصات + سجل | ✅ منجزة |

## 🚀 التشغيل

```powershell
# من داخل مجلد المشروع cyber-shield-ai
.venv\Scripts\python -m uvicorn backend.main:app --reload --port 8000
```

ثم افتح المتصفح على: **http://localhost:8000**

1. اضغط **Sign in ← New account** وأنشئ حساباً (لحفظ فحوصاتك).
2. اضغط **Load vulnerable sample** ثم **Run scan**.
3. شاهد **Security score over time** و **Scan history** أسفل الصفحة، واضغط أي فحص سابق لعرضه، أو **Export PDF** لتصدير التقرير.

> الواجهة إنجليزية بالكامل. الاسم: **Cyber Shield AI**.

> إذا كان المنفذ 8000 مشغولاً، استخدم `--port 8010` مثلاً.

## 🤖 النظام الهجين للذكاء الاصطناعي (قرار المشروع)

طبقة `ai_analysis.py` تعمل بوضعين تلقائياً:

- **`mock` (الآن):** يولّد شرحاً ذكياً من بيانات القاعدة — يعمل بدون مفتاح وبدون تكلفة.
- **`claude` (لاحقاً):** عند ضبط `ANTHROPIC_API_KEY` وتثبيت `anthropic`، يتحوّل تلقائياً لاستدعاء Claude API لتحليل حقيقي وتقدير الثقة وتقليل الإيجابيات الكاذبة.

**الجزء الهجين الأهم:** كل نتيجة تُخزَّن في `dataset.jsonl`. هذه البيانات الحقيقية هي
التي سنستخدمها لاحقاً **لتدريب نموذجنا الخاص** — وهي المساهمة البحثية للمشروع.

لتفعيل الوضع الحقيقي لاحقاً:
```powershell
.venv\Scripts\pip install anthropic
$env:ANTHROPIC_API_KEY = "sk-ant-..."
```

## ⚖️ الاعتبارات الأمنية والقانونية (مهمة جداً لقسم الـ attack)

قسم فحص المواقع (المرحلة 4) يحوّل المنصة من «قارئ كود» إلى «فاحص فعّال»، لذلك يُبنى
بضوابط صارمة قبل أي سطر كود:

1. **التحقق من الملكية:** لا يُفحص أي موقع إلا بعد إثبات المستخدم ملكيته (ملف تحقق/سجل DNS).
2. **الإذن الصريح:** شروط استخدام تمنع فحص مواقع الغير.
3. **تحديد المعدل (Rate Limiting):** حتى لا تتحوّل المنصة لأداة هجوم.
4. **العزل:** كل فحص داخل حاوية Docker معزولة بلا وصول للشبكة الداخلية.
5. **الدفاع لا الاستغلال:** نعرض الإصلاح، لا خطوات استغلال الثغرة.

## 🧪 التقييم (الجانب البحثي) — منجز

قمنا بتقييم كمّي للفاحص على **dataset مُصنّف** (24 عيّنة: 12 مصابة + 12 نظيفة) داخل
مجلد `evaluation/`. النتائج (تُعاد بأمر واحد: `python evaluation/evaluate.py`):

| المقياس | القيمة |
|---|---|
| Precision | **85.7%** |
| Recall (نسبة الكشف) | **100%** |
| F1-score | **92.3%** |
| Accuracy | **91.7%** |

- **Recall 100%:** الفاحص مسك كل الثغرات الحقيقية (صفر false negatives).
- **Precision 85.7%:** إيجابيّتان كاذبتان (على `%s` و `subprocess.run` الآمنة) — وهذا
  بالضبط ما تهدف **طبقة الـ AI** لتقليله. التقرير الكامل: `evaluation/REPORT.md`.
- **الخطوة التالية للبحث:** قياس تحسّن الـ Precision بعد تفعيل فلتر Claude API،
  ومقارنة بأداة مرجعية (Semgrep)، والتوسّع لـ OWASP Benchmark.

5. **تحويل الموقع كاملاً للإنجليزية** وإعادة التسمية إلى **Cyber Shield AI**.

## 🌐 المرحلة 4 — فحص المواقع (attack) [منجزة]

تحوّل المنصة من فحص الكود إلى فحص **المواقع الحيّة** — مبنية **بشكل دفاعي وقانوني**:

- **فحص Passive (آمن، يعمل على أي موقع):** نقرأ فقط ما يقرأه المتصفح عند زيارة الصفحة:
  - ترويسات الأمان (HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy)
  - شهادة TLS (صلاحية/انتهاء/صحة)
  - أعلام الكوكيز (Secure, HttpOnly, SameSite)
  - كشف الإصدارات (Server, X-Powered-By)
  هذا **ليس هجوماً** — هو تحليل تحميل صفحة عادي، وقانوني لأي موقع.

- **فحص Active (يتطلب إثبات الملكية):** فحص المسارات الحساسة (`/.env`, `/.git/HEAD`…).
  لا يعمل إلا بعد أن يُثبت المستخدم ملكيته للموقع عبر توكن (ملف `.well-known` أو meta tag).
  localhost موثوق تلقائياً للتجربة. **لا نُطلق أي هجوم على موقع لم يُثبَت ملكيته.**

> هذا التصميم هو الصح قانونياً وأخلاقياً: الهدف **الدفاع** (تقرير + إصلاح)، لا الاستغلال.

### 🔒 ضوابط الأمان (تحسينات المرحلة 4 — منجزة)
1. **حماية SSRF:** قبل أي فحص، يُحَل اسم الموقع ويُرفض إن كان يشير لعنوان داخلي/محجوز
   (10.x، 172.16-31، 192.168، 169.254 metadata، loopback…). localhost مسموح فقط
   في التطوير (`CYBERSHIELD_ALLOW_LOCALHOST=1`) ويُغلق في الإنتاج.
   الملف: `backend/web_scanner.py` → `ssrf_check()`.
2. **حدّ حجم الاستجابة:** لا يُحمَّل أكثر من 2MB لكل رد (حماية الفاحص من ردود ضخمة).
3. **تحديد المعدّل (Rate Limiting):** 20 فحص/60 ثانية لكل مستخدم (أو IP للزوار) — يمنع
   تحويل المنصة لأداة هجوم. الملف: `backend/rate_limit.py` (يُرجِع 429 عند التجاوز).
4. **العزل والنشر:** `Dockerfile` يشغّل التطبيق في حاوية بمستخدم غير جذري (non-root).

### الخطوات القادمة (المرحلة 4++)
- عزل كل فحص في حاوية منفصلة (بدل حاوية التطبيق الواحدة).
- دعم Redis لتحديد المعدّل عبر عدة خوادم.
- توسيع الفحص النشط (بعد التحقق فقط) وربطه بتدريب النموذج.
